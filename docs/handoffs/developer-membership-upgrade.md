# Developer organizations and app memberships

- Existing Developer is the organization/profile; DeveloperMembership remains organization access. One account can join multiple organizations. Existing unique Developer.AccountId remains intact, so owned registration profile stays one per account.
- `X-Developer-Organization` selects profile/team/create/list context; malformed UUID returns 422, inaccessible selected profile/team returns 403. Omitted header keeps deterministic legacy own-profile-first/oldest-membership default.
- App memberships are additive, unique `(MiniAppId, AccountId)`. Organization owner stays Owner; explicit app role overrides inherited organization role for other accounts. New app creator receives app Owner. App invite acceptance can grant access without a Developer profile or organization membership.
- App actions check backend capabilities: Owner only credentials, Admin/Owner members, Developer/legacy Member/Admin/Owner edits, Viewer and legacy Analyst read aggregate analytics; full audit Owner/Admin only. Restricted organizations/apps keep read access and block writes. Organization permissions remain separate.
- Invitations bind existing AccountId, not email. Acceptance requires the authenticated target account, a live active app/organization, unexpired uncancelled invitation, and inviter still authorized. No email-only linking or email transport is introduced. Expiry seven days; accepted/cancelled timestamp concurrency tokens plus membership unique index protect races. DeveloperMembership.AccountId index is nonunique; (DeveloperId, AccountId) stays unique.
- Routes: GET `/api/developer/organizations`, GET `/mini-apps/{id}/members`, GET/POST `/mini-apps/{id}/invitations`, DELETE invitation by ID, GET `/api/developer/invitations`, POST invitation `/accept`, PUT/DELETE explicit app memberships. Inherited organization members must be managed in organization team. Owner role cannot be assigned, downgraded or removed through these endpoints.
- Ownership transfer is deliberately denied by generic membership routes; a dedicated proof-bound transfer flow is required before permitting it. Existing ownership is preserved.
- Tests in DeveloperMembershipTests cover selected/multiple organizations, multiple organization membership, app-only scope and permissions, bound acceptance, expiry/cancel, replay and owner preservation.
- Generate additive migration together with the platform upgrade. No database write/deployment performed by this slice.
